# Explainer videos -- authoring contract (internal)

Goal (the user's request): "a motion graphics explainer video for each of the lessons using just
html/js/css with a voiceover aimed at taking the average structural engineer from basic knowledge to
understanding SSI using SASSI".

One video per lesson, `sassi/ui/static/videos/NN.html` (NN = 01 ... 11), played in the browser: the motion
graphics are HTML/SVG/CSS animated by JavaScript; the voiceover is pre-generated ElevenLabs speech (one MP3 per
beat, `audio/NN/`, with word timings: section "Voiceover"), with the browser's text-to-speech (Web Speech API)
as the fallback for any beat without audio. Captions and a transcript come from the same text. No build step,
no external requests: the pages work from `file://`, from the local GUI and in the GitHub Pages bundle.

## Files

| file | what |
|---|---|
| `player.css` | the player and the visual language (semantic colours, components, reveal classes) |
| `player.js` | the engine: timeline of scenes and beats, speech, captions, transcript, controls, seeking |
| `kit.js` | the motion-graphics kit `SV.K`: soil, sticks, buildings, springs, dashpots, waves, plots, code, equations |
| `NN.html` | the page of video NN (a 20-line shell, copy `01.html`) |
| `dNN.js` | the computed curves of video NN (generated by `python -m sassi.ui.video_data`, never edited) |
| `vNN.js` | the script of video NN: scenes, narration, cues |
| `aNN.js`, `audio/NN/` | the recorded narration of video NN (generated by `web/voice_videos.mjs`, never edited) |
| `index.html` | the list of all videos |

`../figures.js` (the lesson figures) is loaded too: `SV.K.PH` is its pure physics (complex arithmetic,
SHAKE column `columnRatios`, `ssiResponse`, `synthMotion`, `spectrum`, `hyperbolic`, `masing`,
`interpTF` ...), usable for curves the runs do not give. `../katex/` typesets equations.

## Audience and voice (newcomer edition)

The user's feedback on the first edition: "quite slow and complicated, please make them more newcomer
friendly, easier to understand ... speed them up a bit so the listener doesn't fall asleep". The videos are
the **friendly front door** of each lesson, not a summary of it: a newcomer should finish one understanding
the one big idea, why it matters for their design, and roughly how SASSI does it. Details belong to the
lesson.

The viewer is a structural engineer who knows fixed-base seismic design (a building model clamped at the
base, earthquake loading, response spectra) and is **new to soil-structure interaction and to SASSI**.
Assume no SSI vocabulary at all.

**Targets per video**

* **4-6 minutes** (the harness estimate), **600-850 spoken words**, 7-9 scenes, 35-60 beats. Short beats:
  one sentence each, **at most ~20 words** (never more than 25). The voice is quick and lively; the pauses
  between beats are short (`gap` default 200 ms); use `hold` only where an animation needs the time (≤ 1.5 s).
* **One big idea per video, one idea per scene.** Cut every side topic, exception, option, file name and
  check that a newcomer does not need to follow the story. When in doubt, leave it to the lesson.
* **Few numbers**: 3-6 key numbers per video, the ones that tell the story (e.g. "the frequency drops from
  5 to 3.5 hertz"). Round them the way the lesson does; every number still comes from the lesson or `dNN.js`.
* **Plain words first, the term second.** Introduce every technical term with an everyday picture, then name
  it: "The soil under the building behaves like a car's suspension: springs, and shock absorbers. Engineers
  call them springs and dashpots." Re-introduce a term briefly when a later video uses it ("remember, the
  free field is the ground shaking with no building on it").
* **Speak like a good teacher, not like a manual.** Short words, active voice, "you". Ask the question
  before giving the answer. Use the "why should I care" moment: what this changes in ISRS, forces or
  displacements.
* **SASSI commands**: at most one or two short command blocks per video (≤ 3 lines), each explained in
  words in one sentence. Module names (SITE, ANALYS ...) only where they help; never lists of options.
* **Equations**: at most one per video, only if it is explained in plain words as it appears. Prefer a
  picture.
* **On screen**: one picture plus a few big words. Headings ≤ 7 words, labels ≤ 5 words, cards ≤ 15 words,
  no table larger than 3 x 3, no paragraphs. Big text (labels ≥ 28 px, key numbers large). Something moves
  in every scene.
* Accuracy rules stay: every number from the lesson text or the lesson's run; non-computed curves and
  pictures labelled "schematic" (or "illustration") on screen; ACS SASSI names; no prose from
  `reference/acs-sassi.txt`.

**Shared plain-language glossary** (use these pictures consistently across the series):

| term | first explain it as |
|---|---|
| fixed base | the usual model: the building clamped to rigid ground |
| SSI | the building and the soil shake each other: the ground is not rigid |
| free field | how the ground shakes with no building on it |
| frequency domain | SASSI works one frequency at a time, like taking a chord apart into notes |
| transfer function | how much a point amplifies the ground motion at each frequency (an equaliser curve) |
| ISRS | how hard equipment on a floor gets shaken, for each equipment frequency |
| springs and dashpots / impedance | the soil acts like a car's suspension: springs, and shock absorbers |
| radiation damping | energy carried away by waves spreading into the ground, like ripples from a stone in a pond |
| kinematic interaction | a stiff foundation cannot follow every wiggle of the ground: it averages them |
| inertial interaction | the building's own swaying pushes back on the soil |
| interaction nodes | the points where the building and the soil hold hands |
| substructuring | solve the soil and the building separately, then join them at those points |
| excavated soil, FV | SASSI fills the hole with soil, then subtracts it: the flexible-volume method |
| half-space | rock that goes down forever, so waves leave and never come back |
| equivalent-linear | stronger shaking softens the soil: guess the softness, check, repeat until it agrees |

### Pace and accuracy (third edition)

The user's next feedback: "make them more fast paced and the graphics more accurate".

**Pace.** The player plays the recorded voice at **1.15×** by default (pitch preserved), with 120 ms between
sentences, and every animation runs faster. In the scripts:

* 3-4 minutes per video at 1.15×, **30-45 beats**: cut the sentences a newcomer does not need (repeats,
  second examples, filler). Deleting a beat costs nothing; a reworded or new sentence has to be recorded
  again, so keep those few.
* `hold` at most 600 ms, the quiz `gap` at most 1500 ms. Strokes draw in ≤ 1000 ms, staggers ≤ 150 ms, delays
  ≤ 400 ms. Every beat changes something on screen; no beat where only the voice moves.

**Accuracy.** The analogies stay in the words; the **pictures show the real engineering object**:

* **Geometry to scale**: the lesson's model with its real proportions (storey heights, mat or basement
  size, embedment, layer thicknesses; a deep half-space may be cut with a fade). Dimension lines or a scale
  where it helps. No cartoon props (jelly, cars, buses, ovens, showers ...) as pictures.
* **Motion from the computation**: an animated structure or soil column moves with the computed amplitudes
  **and phases** at the frequency named (the `TFU`/`TFI` files in `dNN.js` carry `amp` and `ph`; the soil
  column uses the one-dimensional wave solution `PH.columnU` of the lesson's site). One exaggeration factor
  for all displacements of a scene, stated on screen ("displacements × 200, slowed down 8 ×"). Never a gain
  on one component only (e.g. extra rocking).
* **Physics right**: SV moves particles along X, SH along Y, P vertically, all rising vertically; springs for
  sliding horizontal at the foundation, rocking/vertical springs vertical under the edges; dashpots beside
  springs; radiated waves leave downwards and outwards.
* **Counts and positions** match the model: 81 nodes on a 9 × 9 grid at 2.5 m (example 1), 150 = 5 × 5 × 6 in
  the excavation of example 2, 49 = 7 × 7 at 2 m (example 3), 405 / 209 / 258 in example 8 ...
* **Plots**: computed curves; every annotation placed at the data point it names (computed from the data,
  never a hand-placed coordinate); axes with units; the y range never clips a peak. If a curve is too coarse
  to show its peak shape, regenerate `dNN.js` with more points.
* Anything that is still an illustration (the "notes" of a chord, a spring-and-dashpot symbol) says
  "schematic" or "illustration" on screen.

### Structure of every video

1. **Hook** (no title yet, 2-4 beats): one question a designer would ask, in one picture.
2. **Title card** (1 beat).
3. **Two to four idea scenes**: the physics, built up visually with the everyday picture first.
4. **"How SASSI does it"** (1-2 scenes): the modules or one short command, in words.
5. **What it means for your design** (1-2 scenes): the lesson's key result, 3-6 numbers, one plot at most
   per scene, clearly labelled.
6. **Recap** (3 short points) + **Check yourself** (one simple question: a pause, `gap: 2000`, then the
   answer) + **Up next** (one sentence; the last video closes the course).

## The engine (player.js)

```js
SV.video({id: "02", n: 2, part: "Fundamentals", lesson: "02-free-field",
  title: "The site: layers, half-space and free-field motion", subtitle: "...",
  next: {href: "03.html", title: "Foundation impedance: soil springs and dashpots"},   // omit in 11
  pron: [[/\bSHAKE\b/g, "shake"]],          // extra spoken forms (optional)
  scenes: [
    {id: "column", title: "The layered column",           // title = chapter name (bottom right, transcript)
     build(s) { ... },                                     // create every element of the scene, hidden
     tick(s, t, dt) { ... },                               // optional: continuous animation (t = scene seconds)
     beats: [
       {say: "Five metres of [a]sand, over twelve metres of [b]gravel.",
        go(k) { ... },                                     // runs when the beat starts
        a(k) { k.show(k.s.sand); },                        // runs when the voice reaches [a]
        b(k) { k.show(k.s.gravel); },
        hold: 2000,                                        // optional: the beat lasts at least 2 s
        gap: 380},                                         // optional: pause after the sentence (ms)
     ]},
  ]});
```

* `build(s)` gets `s.root` (the 1920 x 1080 scene `div`), `s.svg` (a full-size SVG layer, behind the HTML),
  `s.$`/`s.$$`. Store references on `s` (`s.plot = ...`); beats read them as `k.s`.
* Markers `[name]` in `say` are removed from captions and speech; `beat[name](k)` fires when the voice
  reaches that word (word-boundary events, or the calibrated speaking rate). Put the marker **before** the
  word the visual belongs to.
* `{shown|spoken}` writes a one-off pronunciation (`{X_ff|X F F}`). Common abbreviations are spoken
  correctly already (`SV.PRON`: SASSI, SSI, ISRS, ANALYS, FV, FI-FSIN, Hz, m/s, g, Vs, Δf, ω ...).
  Write units after numbers (`3.49 Hz`, `0.324 g`, `300 m/s`, `5 m`) and they are read out.
* **Seeking replays earlier beats instantly** (`k.instant = true`), so every cue must reach its end state
  through the `k` helpers (or set its final state directly when `k.instant`). Never use `setTimeout`,
  CSS animations or `requestAnimationFrame` in a video: use `k.at`, `k.tween`, `tick`.
* State that a `tick` reads (amplitudes, phases) lives on `s` and is changed with `k.tween(k.s, {A: 1}, ms)`.

### The k helpers (cue context)

| helper | does |
|---|---|
| `k.show(t, {stagger, delay})` / `k.hide(t)` | reveal / fade out elements (`t`: element, selector, array, kit object with `.g`/`.el`) |
| `k.dim(t, on)` | dim to 22 % (`on` false: undim) |
| `k.draw(path, ms, {delay, from, to})` | draw a stroke (paths built with `draw: true` start undrawn) |
| `k.tween(obj, {p: v}, ms, {ease, delay, update})` | animate numbers on an object (scene state) |
| `k.move(el, {x, y, scale, rotate, opacity}, ms)` | move / scale / fade an element (CSS individual transforms) |
| `k.count(el, to, {from, dec, ms, pre, post})` | count a number up in an element's text |
| `k.type(lines, {cps})` | type `K.code` lines |
| `k.cls(t, cls, on)` | toggle a class: equation terms `eqhl` (amber), `eqhl2` (blue), `eqhl3` (yellow), `eqdim` |
| `k.at(ms, fn)` | run `fn` later in the beat (scene clock) |
| `k.pulse(t)` | a short attention pulse |
| `k.loop(fn)` | a continuous animation `fn(t, dt)` for the rest of the scene |

## The kit (kit.js, `SV.K`)

HTML (take `s.root`, start hidden; `{in: "up"|"left"|"right"|"down"|"fade"|"pop"}`, `{visible: true}`):
`titleCard`, `kicker`, `heading(text, {x, y, size: "h1"|"h2"|"h3"})`, `para`, `label`, `bullets(items, {num})`,
`card({x, y, w, title, body, kind: "ansys"|"check"|"warn", size})`, `stat({value, unit, label, color, vsize})`
(`.el`, `.v` for `k.count`), `code(lines, {x, y, w, size})` (`.lines` for `k.type`), `eq(tex, {x, y, size, box})`
(KaTeX; mark terms `\htmlClass{t-name}{...}`), `table({head, rows})` (`.rows`), `pill`, `chain(names)`
(`.boxes`, `.arrows`), `h(tag, {x, y, w, html, cls})` for anything else.

SVG (take `s.svg` or a group; visible unless `{hidden: true}`; strokes `{draw: true}` start undrawn):
`g`, `line`, `rect`, `circle`, `path`, `poly(pts, {smooth})`, `text(x, y, str, {cls, anchor, size, color})`,
`arrow`, `curveArrow`, `dim` (dimension line), `ground` (fixed-support hatch),
`soil({x, y, w, layers: [{h, kind: sand|gravel|rock|deep, name, vs}], hs, labels})` (`.layers[i].g`, `.shear(fn)`),
`stick({x, y, z: [px], matW, r, slabW})` (`.set({sway, rock, bend})`, `.nodes()`, `.masses`),
`building({x, y, w, storeys, storeyH, basement})` (`.set({sway, rock, drift})`),
`spring` / `dashpot` (`.update(x1, y1, x2, y2)`), `wavefronts` (`.set(t, speed)`), `ripples` (`.set(t)`, `.amp`),
`signal({x, y, w, h, fn})`, `plot({x, y, w, h, xr, yr, xlog, ylog, xticks, yticks, xlabel, ylabel})`
(`.line(xs, ys, {color, draw, dash})`, `.area`, `.dot`, `.vline`, `.hline`, `.text`, `.legend`, `.X`, `.Y`),
`nodes(pts)`, `mesh({x, y, cols, rows, dx, dy})`, helpers `linspace`, `logspace`, `modeTF`, `d(pts, smooth)`.

Kit quirks to know: `K.eq` in display mode keeps KaTeX's 1em top and bottom margin (use `display: false`
with `\dfrac` for tight layouts); the header row of `K.table` is visible from the start (only the rows enter);
a curve drawn with `draw: true` cannot also be dashed (the draw animation uses the dash pattern).

## Visual language

* Stage 1920 x 1080; keep content inside x 90-1830, y 70-990 (the brand and chapter labels sit at the bottom
  corners). Text at least 22 px; body 28-38 px; headings 54-76 px. No paragraph longer than ~25 words on
  screen: the voice carries the explanation, the screen carries the picture, the numbers and the keywords.
* **Semantic colours** (the same meaning in every video; `K.C.*`):
  `wave` (blue) free field, incoming waves, control motion; `ssi` (amber) SSI result, inertial interaction,
  the highlighted term; `ref` (grey) fixed-base or reference result; `spring` (yellow) springs, real part of
  the impedance; `dash` (pink) dashpots, radiation damping, imaginary part; `kin` (teal) kinematic
  interaction, massless runs; `good` / `bad` (green / red) checks passed / anomalies, unconservative;
  `violet` a third series; soil `sand`, `gravel`, `rock`, `deep`; structure `steel` / `concrete`.
* Something changes on screen at every beat; build diagrams up piece by piece in sync with the words.
  Prefer diagrams, plots and animation to text. Continuous motion (a shaking column, a vibrating stick,
  radiating ripples) is what makes it a motion graphic: give every concept scene some.
* Plots show computed data (`dNN.js`) with labelled axes and units; annotate the numbers the narration says.
  Vibrations drawn "to scale" say so; slowed-down motion says so.

## Data (dNN.js)

```bash
# disk is tight on this Mac: one lesson run at a time, in the scratchpad, deleted afterwards
python -m sassi.ui.video_data 02-free-field --keep $SCRATCH/run02 --list ex01      # run once, list files
python -m sassi.ui.video_data 02-free-field --from $SCRATCH/run02 --js 02 --points 200 FILE ... > sassi/ui/static/videos/d02.js
rm -rf $SCRATCH/run02
```

`--from` reads a kept workspace without running again; the header of `dNN.js` records the equivalent
command. Keep `dNN.js` under ~60 kB (`--points`). Values for the narration come from the lesson text; the
curves must agree with them (check the peaks the tool prints).

## Voiceover (ElevenLabs)

The narration is recorded once with ElevenLabs and shipped as files; the player needs no key and makes no
request. `web/voice_videos.mjs` reads every video exactly as the player does (the spoken form of each `say`,
after `SV.PRON` and `{shown|spoken}`), and records **one MP3 per beat** with the `/with-timestamps` endpoint:

```bash
node web/voice_videos.mjs --dry                                   # what is missing, in characters
ELEVENLABS_API_KEY=... node web/voice_videos.mjs                  # record what is missing (all videos)
ELEVENLABS_API_KEY=... node web/voice_videos.mjs 03 --voice <id> --voice-name <name>   # another voice
```

* Voice "Matilda" (an upbeat educator voice), model `eleven_multilingual_v2`, speed 1.1, MP3 44.1 kHz
  64 kb/s (about 0.5 MB per minute). The neighbouring sentences go along as `previous_text`/`next_text`, so the
  intonation flows from beat to beat.
* Files: `audio/NN/<hash>.mp3` (hash = `SV.hash` of the spoken text) and the manifest `aNN.js`
  (`SV.AUDIO["NN"]`: per clip its duration and the time of each `[marker]`, from the character timings). The
  script adds `aNN.js` to `NN.html`.
* **Editing a sentence** changes its hash: the player falls back to the browser voice for that beat until
  the generator is run again, which records only the changed beats and deletes unused clips. A change of
  voice, model or settings re-records everything.
* The key comes from the environment (or `--key-file`), is never printed and never stored in the project
  (`tests/unit/test_videos.py` checks that no key-like string is in it).
* In the player, ⚙ offers the recorded voice and the browser's voices; the speed menu changes the playback
  rate (pitch preserved). `tests/unit/test_videos.py` checks that every beat has its clip.

## Verification

```bash
node web/test_videos.mjs 02                                  # every beat applied, no errors
node web/test_videos.mjs 02 --shots $SCRATCH/shots --all     # a JPEG per beat (960 x 540)
node web/test_videos.mjs 02 --play 20                        # 20 s of real-time playback (voice off)
node web/test_videos.mjs 02 --audio 15                       # 15 s with the recorded narration
```

Look at every scene's last beat and every beat that moves things: no overlaps, nothing outside the frame,
labels legible, plots readable, numbers matching the narration and the lesson. `?debug` shows the scene and
beat in the browser, `#3.2` opens scene 3 at beat 2.
